# Esempio di istanza del database

Vediamo un esempio per capire meglio come sono mappati nel database.
 
---
 
### Tabella SUGGESTIONS
 
| ID (PK, FK) | Level  | ClassUT (FK) |
|------------|--------|--------------|
| 2          | LOW    | Calcolatrice |
| 3          | MEDIUM | Calcolatrice |
| 4          | HIGH   | FTPFile      |
 
L'ID di **SUGGESTIONS** è una chiave esterna a **GUIDELINES (ID)**.
 
---
 
### Tabella GUIDELINES
 
| ID (PK) | order | Hint                              | Image      | Date       | DTYPE       |
|--------|-------|-----------------------------------|------------|------------|-------------|
| 1      | 1     | Testo linea guida 1               | NULL       | 08/12/2025 | Guideline   |
| 2      | 1     | Testo suggerimento 1 di Calcolatrice | NULL    | 08/12/2025 | Suggestion  |
| 3      | 2     | Testo suggerimento 2 di Calcolatrice | NULL    | 08/12/2025 | Suggestion  |
| 4      | 1     | Testo suggerimento 1 di FTPFile   | image.png  | 08/12/2025 | Suggestion  |
| 5      | 2     | Testo linea guida 2               | image2.png | 08/12/2025 | Guideline   |
 
> **DTYPE**  
> Non è un vero campo del database, vedi sezione DTYPE successiva.
 
---

### Descrizione dell'esempio
Nell'esempio la tabella **SUGGESTIONS** contiene solo i suggerimenti, con chiave primaria ID che è anche la chiave esterna alla tabella **GUIDELINES**. Quindi si nota come siano presenti due suggerimenti associati alla classe "Calcolatrice", con id rispettivamente 2 e 3, e una associata alla classe FTPFile.

Quindi nella tabella **GUIDELINES** sono presenti le tuple riferite dalla tabella **SUGGESTIONS** dove sono raggruppati i campi *order* (che definisce l'ordine dei suggerimenti per classe), *Image* (che indica l'eventuale immagine associata al suggerimento) e *Date* (che indica la data di creazione del suggerimento).

Nella tabella **GUIDELINES** sono presenti anche delle tuple relative alle linee guida, che sono validi in generale per tutte le classi, in quanto non è presente una tupla corrispondente nella tabella **SUGGESTIONS**. Anche le linee guida presentano il campo *order*, che definisce l'ordine sequenziale delle linee guida, indipendentemente da quello dei suggerimenti.

### Il campo `order`

- Per le tuple di **GUIDELINES "pure"** (di tipo *Guideline*), indica l'ordine progressivo di ogni Linea Guida **nell'elenco generale di tutte le Linee Guida**.
- Per le tuple di **GUIDELINES di tipo Suggestion**, indica l'ordine progressivo del suggerimento **all'interno della sua ClassUT** (FK presente in **SUGGESTIONS**).  
  Quindi l'ordine è **per classe**, in quanto ogni classe ha una propria sequenza di suggerimenti associati.


### Il campo `DTYPE`
Il DTYPE è un attributo "nascosto", utilizzato solo nelle query di JPA in linguaggio JPQL, ma non è un vero campo nel database, in quanto non viene creato. Infatti, a partire dalle seguenti classi model in Java:
```java
@Entity
@Table(name = "guidelines")
@Inheritance(strategy = InheritanceType.JOINED)
public class Guideline { ... }

@Entity
@Table(name = "suggestions")
public class Suggestion extends Guideline { ... }
```
vengono generate le seguenti query MySQL create da **Hibernate** (l'implementazione di JPA utilizzata) all'atto della creazione del database, in cui è assente il campo **DTYPE**
```SQL
create table guidelines (
    date date not null,
    ordine integer not null,
    id bigint generated by default as identity,
    hint varchar(255) not null,
    image varchar(255),
    primary key (id)
)
```
```SQL
create table suggestions (
    id bigint not null,
    class_name varchar(255),
    level varchar(255) not null check (level in ('LOW','MEDIUM','HIGH')),
    primary key (id)
)
```

### Esempio di query che sfrutta il campo DTYPE
Questa query, scritta in linguaggio JPQL, è definita in GuidelineRepository per accedere a tutte le Linee Guida

```java 
@Query("SELECT g FROM Guideline g WHERE TYPE(g) = Guideline")
List<Guideline> findAllGuidelines();
```

Viene tradotta da Hibernate nella seguente query MySQL, in cui in realtà viene effettuata una LEFT JOIN con la tabella suggestions, per individuare tuple di guidelines che non sono suggerimenti. Il campo "dtype" è generato ad-hoc nella SELECT, in quanto è utilizzato successivamente per capire che, in questo caso, bisogna istanziare oggetti della classe model Guideline e non Suggestion.


```SQL
SELECT
    g1.id,
    CASE
        WHEN s.id IS NOT NULL THEN 1
        WHEN g1.id IS NOT NULL THEN 0
    END AS dtype,
    g1.date,
    g1.hint,
    g1.image,
    g1.ordine,
    s.class_name,
    s.level
FROM guidelines g1
LEFT JOIN suggestions s ON g1.id = s.id
WHERE
    CASE
        WHEN s.id IS NOT NULL THEN 1
        WHEN g1.id IS NOT NULL THEN 0
    END = 0;
```
