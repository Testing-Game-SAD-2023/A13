# Observability Stack
This section describes the **observability infrastructure** implemented in the application.
Its goal is to **centralize the logging and tracing** of all microservices to simplify debugging and monitoring.

Currently, the stack collects and manages only **logs** and **traces**.
In simple terms, **traces** provide a *“big picture”* of what happens when the system processes a request.
For example, when a microservice handles an incoming HTTP request, its trace shows which other services or endpoints 
it calls in order to complete that request.

For a deeper explanation of the concepts of logs and traces, refer to the official OpenTelemetry documentation:
[https://opentelemetry.io/docs/concepts/signals/](https://opentelemetry.io/docs/concepts/signals/)

## Components
The observability stack is composed of the following components:

| Component                   | Description                                                                                     |
| --------------------------- | ----------------------------------------------------------------------------------------------- |
| **Logback**                 | Defines the format and structure of logs generated by each microservice.                        |
| **OpenTelemetry SDK**       | Automatically generates traces for incoming and outgoing HTTP requests and internal operations. |
| **OpenTelemetry Collector** | Serves as a central collector that receives logs and traces from all microservices.             |
| **Grafana Loki**            | Stores and indexes log data for fast querying and correlation.                                  |
| **Grafana Tempo**           | Stores and manages distributed traces, enabling request-level visibility across services.       |
| **Grafana**                 | Provides a unified web dashboard to visualize logs, traces, and correlations between them.      |

## Architecture Overview
The centralized logging and tracing pipeline works as follows:
1. Each microservice produces structured logs (via Logback) and traces (via OpenTelemetry SDK).
   These logs and traces are sent to the OpenTelemetry Collector;
2. The Collector receives, processes, and routes:
   - The logs to Grafana Loki;
   - The traces to Grafana Tempo;
3. Grafana queries Loki and Tempo to visualize logs and traces in real time from a single dashboard.

Simplified flow:

```
[Microservice] → [OTel Collector] → [Loki / Tempo] → [Grafana]
```

### 1. Logback
**Logback** is the logging framework used to define the structure and encoding of log messages produced by each microservice.

To use it, add the following dependency to your microservice’s `pom.xml` file:
```xml
<!-- Logback JSON Encoder -->
<dependency>
    <groupId>net.logstash.logback</groupId>
    <artifactId>logstash-logback-encoder</artifactId>
    <version>6.6</version>
</dependency>
```

The configuration is defined in the following file:
```
src/main/resources/logback-spring.xml
```

The current configuration format the logs as JSON structured specifically for Loki, enriched with trace correlation via 
`trace_id` and `span_id:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <include resource="org/springframework/boot/logging/logback/defaults.xml"/>

    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder class="net.logstash.logback.encoder.LoggingEventCompositeJsonEncoder">
            <providers>
                <timestamp/>
                <logLevel/>
                <loggerName/>
                <threadName/>
                <message/>
                <stackTrace/>
                <mdc>
                    <includeMdcKeyName>trace_id</includeMdcKeyName>
                    <includeMdcKeyName>span_id</includeMdcKeyName>
                </mdc>
            </providers>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
    </root>
</configuration>
```

### 2. OpenTelemetry Collector
The **OpenTelemetry SDK** automatically instruments the application to generate traces for:
- Incoming HTTP requests;
- Outgoing REST calls between services;
- Internal operations, such as database queries.

OpenTelemetry is enabled via teh following Maven dependency:
```xml
<dependency>
    <groupId>io.opentelemetry.instrumentation</groupId>
    <artifactId>opentelemetry-spring-boot-starter</artifactId>
    <version>2.7.0</version>
</dependency>
```

The SDK can be configured using environment variables or `application.yml`/`application.properties`:
```properties
otel.exporter.otlp.traces.endpoint=http://otel-collector:4317
otel.resource.attributes.service.name=T4
otel.traces.exporter=otlp
otel.exporter.otlp.protocol=grpc
```

The `service.name` attribute is crucial, as it identifies the source microservice in Grafana Tempo.

### 3. OpenTelemetry Collector (otel collector)
The **OpenTelemetry Collector** is the central data pipeline that receives telemetry data from all microservices.

It performs the following functions:
- Receives data from OTLP exporters (both logs and traces);
- Optionally processes or filters it;
- Routes logs to **Grafana Loki** and traces to **Grafana Tempo**.

The OpenTelemetry Collector configuration is organized into the following key sections:

| Section        | Description                                                                     |
| -------------- | ------------------------------------------------------------------------------- |
| **receivers**  | Define how telemetry data (logs, traces, metrics) enters the collector.         |
| **processors** | Modify, aggregate, or filter the incoming data before exporting it.             |
| **exporters**  | Define where to send the processed data (e.g., Grafana Loki, Grafana Tempo).    |
| **service**    | Defines the pipelines — how receivers, processors, and exporters are connected. |

- **Receivers**: the collector accepts telemetry data in the **OpenTelemetry Protocol (OTLP)** format via two transport
  protocols: **gRPC (port 4317)** and **HTTP (port 4318)**. By binding to `0.0.0.0`, the Collector listens on all network 
  interfaces, making it reachable by all microservices within the Docker network.
  ```yaml
  receivers:
    otlp:
      protocols:
        grpc:
          endpoint: 0.0.0.0:4317
        http:
          endpoint: 0.0.0.0:4318
  ```
- **Processors**: the **batch processor** groups telemetry data before exporting it, improving efficiency and reducing network overhead.
    ```yaml
    processors:
      batch:
    ```
- **Exporters**: the collector is configured to send the batched data to three destination:
  - *debug*, which prints telemetry data to the Collector logs;
    ```yaml
    exporters:
    debug:
    verbosity: detailed
    ```
  - **otlphttp/logs**, which sends the logs to Grafana Loki via the OTLP HTTP endpoint;
    ```yaml
    otlphttp/logs:
      endpoint: "http://loki:3100/otlp"
      tls:
        insecure: true
    ```
  - **otlp/traces**, which sends traces to Grafana Tempo over gRPC on (the custom) port 4319; 
    ```yaml
    otlp/traces:
      endpoint: "tempo:4319"
      tls:
        insecure: true
    ```
- **Service**: the service key define how data flows through the collector, from receivers to exporters. All data is
  received via **otlp**, groped via **batch processor** and sent to the respective receiver. Currently, metrics data are 
  not used and logged only for debug.
  ```yaml
  service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlp/traces, debug]
    logs:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/logs, debug]
    metrics:
      receivers: [otlp]
      processors: [batch]
      exporters: [debug]
  ```

### 4. Grafana Loki
**Grafana Loki** is the log aggregation system.
It receives structured JSON logs (via the OpenTelemetry Collector) and indexes them by label (e.g., `service.name`, `level`, `trace_id`).

### 5. Grafana Tempo
**Grafana Tempo** is the distributed tracing backend.
It stores trace data received from the OpenTelemetry Collector.

### 6. Grafana
**Grafana** provides a unified dashboard interface for both logs and traces. To access it, visit the Grafana URL 
(`http://localhost:3000`) and log in. The credentials are:
```html
username=admin
password=admin
```

**Loki** and **Tempo** datasources are already configured via `grafata/datasource.yml`.
